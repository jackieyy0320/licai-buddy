## 一、项目概述

| 项目 | 内容 |
|------|------|
| **项目名称** | Licai Buddy |
| **一句话描述** | 多用户记账工具，消费→库存→投资数据联动 |
| **目标用户** | 25-40岁，有记账+理财需求，注重隐私的个人用户 |
| **商业模式** | 免费开源 |
| **核心价值** | 多用户记账，消费→库存→投资数据联动 |
| **用户模式** | 邀请注册，管理员生成邀请码 |
| **MVP 范围** | 用户认证 + 记账明细 + 账户管理 + 报表统计 |

## 三、用户故事

### 功能 0：用户认证

#### US-000-1：邀请注册

**作为** 新用户，
**我想要** 输入邀请码注册账号，
**以便** 在授权后使用系统。

**验收标准：**
- [ ] 输入有效的邀请码才能注册
- [ ] 邀请码一次性使用，使用后失效
- [ ] 邀请码 7 天有效期，过期自动失效
- [ ] 注册时设置邮箱和密码
- [ ] 密码使用 bcrypt 哈希存储（盐值≥10）
- [ ] 注册成功后自动登录

#### US-000-2：邮箱登录

**作为** 已注册用户，
**我想要** 通过邮箱和密码登录，
**以便** 访问我的记账数据。

**验收标准：**
- [ ] 输入正确邮箱和密码登录成功
- [ ] 错误密码提示明确（不区分邮箱/密码错误）
- [ ] 连续 5 次失败锁定 15 分钟
- [ ] 登录成功后颁发 JWT Token
- [ ] Token 有效期 24 小时，Refresh Token 有效期 7 天
- [ ] 会话超时自动退出

#### US-000-3：生成邀请码

**作为** 管理员，
**我想要** 生成邀请码分享给他人，
**以便** 控制谁能注册使用。

**验收标准：**
- [ ] 可生成指定有效期的邀请码（默认 7 天）
- [ ] 邀请码唯一，不可重复
- [ ] 显示完整邀请码便于复制分享
- [ ] 记录创建人和创建时间

#### US-000-4：管理邀请码

**作为** 管理员，
**我想要** 查看和管理已生成的邀请码，
**以便** 了解邀请状态并及时失效。

**验收标准：**
- [ ] 显示所有邀请码列表
- [ ] 显示每个邀请码的状态（未使用/已使用/已过期）
- [ ] 可手动失效邀请码

## 四、非功能性需求

### 4.1 性能需求

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 页面加载时间 | < 2秒 | 首屏加载时间 |
| 首次交互时间 | < 100ms | 用户操作响应时间 |
| 数据库查询 | < 100ms | 单次查询时间 |
| API 响应时间 | < 500ms | 接口响应时间 |
| 余额计算 | < 50ms | 动态计算账户余额 |

**余额计算策略：**
- Account 表不存储 balance 字段，每次从 Transaction 动态计算
- 计算公式：`余额 = SUM(收入) - SUM(支出) + SUM(转入) - SUM(转出)`
- 数据库索引：`(user_id, account_id)`, `(user_id, to_account_id)`, `(date)`
- 即使 1万条交易/账户，查询也 < 50ms

**数据一致性保障：**
- 补录历史交易后，余额自动重新计算，无需额外逻辑
- 编辑/删除交易后，余额自动刷新

### 4.2 安全需求

| 项目 | 要求 |
|------|------|
| 数据存储 | 本地 SQLite，无云端同步 |
| 密码存储 | bcrypt 哈希，盐值 ≥ 10 |
| 会话管理 | JWT Access Token (24h) + Refresh Token (7d) |
| 登录保护 | 连续 5 次失败锁定 15 分钟 |
| XSS 防护 | 输入过滤 + 输出转义 |
| CSRF 防护 | SameSite Cookie + Token 校验 |
| 输入验证 | 所有输入进行前端+后端验证 |
| 隐私保护 | 无第三方数据上报 |
