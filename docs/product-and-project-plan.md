## 第一部分：产品战略

### 一、产品愿景

**一句话定位：** 一体化工具记账，让每一笔消费关联到资产与收益

**愿景：** 打造一款真正"活"的记账工具——不是孤立记录每一笔支出，而是让消费、库存、投资形成数据闭环，帮助用户看清钱从哪里来、到哪里去、还剩多少。

---

### 二、目标用户

| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| **个人用户** | 有记账习惯，注重隐私 | 简洁、快速、本地存储 |
| **小商家** | 有进货库存需求 | 采购入库、库存管理 |
| **理财人群** | 有投资需求 | 投资记录、收益跟踪 |
| **追求数据联动者** | 想看清全貌 | 消费→库存→投资的关联分析 |

**核心用户画像：**
- 25-40岁，有一定消费和理财需求
- 对数据敏感，喜欢分析自己的财务状况
- 注重隐私，不希望财务数据上传云端
- 愿意花时间记录，但希望过程尽量简单

---

### 三、竞品分析

| 产品 | 类型 | 核心功能 | 优势 | 劣势 |
|------|------|----------|------|------|
| **鲨鱼记账** | 移动APP | 快速记账、统计图表 | 极简操作，3秒记账 | 功能单一，无库存/投资联动 |
| **随手记** | 移动APP | 多账本、社区、理财 | 功能全面，用户基数大 | 功能臃肿，广告多 |
| **钱迹** | 移动APP | 无广告、简洁 | 纯净体验 | 无联动功能 |
| **MoneyWiz** | 桌面/移动端 | 多账户、投资、预算 | 专业级功能 | 付费、学习成本高 |
| **Excel/Google Sheets** | 工具 | 自由度高 | 完全自定义 | 无自动化，手动录入繁琐 |

**市场机会：**
- 现有产品要么是"纯记账"，要么是"复杂财务管理"
- 缺乏**一体化联动**的产品——消费能自动关联库存和理财
- 本地存储+隐私保护的市场空白

---

### 四、核心价值主张

| 维度 | 我们的差异 |
|------|------------|
| **数据联动** | 消费记录 → 自动生成库存 → 关联理财收益计算 |
| **价格追踪** | 同一商品多次购买，自动记录价格变化趋势 |
| **隐私优先** | 本地 SQLite，数据完全存储在用户设备 |
| **免费开源** | 无广告、无订阅、无数据上传 |
| **一体化报表** | 收支、库存、投资三合一视图 |

### 五、产品路线图

#### Phase 1: MVP

#### Phase 3: 理财收益

- 收益记录

- 与账户流水联动

#### Phase 4: 数据联动
- 消费→库存→投资的完整链路
- 价格对比分析
- 关联报表

#### Phase 5: 体验优化
- UI/UX 优化
- 移动端适配
- 性能优化

### 三、管控机制

#### 3.1 需求管控

```
需求变更流程：
1. Jackie 提出需求变更
2. Hermes 评估影响（范围/时间/资源）
3. Hermes 向 Jackie 汇报变更风险
4. Jackie 决策是否接受变更
5. 更新需求文档，通知 Figma 和 Kiro
```

#### 3.2 设计管控

```
设计审核清单：
□ 是否符合需求文档中的功能描述
□ 是否符合用户故事中的交互逻辑
□ 是否符合设计规范（颜色/字体/间距）
□ 是否考虑了移动端适配
□ 是否有明确的交互状态（hover/active/disabled）

设计交付格式：
- Figma 分享链接
- 设计规范文档（颜色、字体、间距）
- 组件库（如有）
```

#### 3.3 开发管控

```
代码审核清单：
□ 功能是否符合需求文档
□ 代码是否符合规范（命名/注释/结构）
□ 是否有单元测试
□ 是否有性能问题
□ 是否有安全问题

开发交付格式：
- 代码仓库链接
- 部署链接
- 测试报告
- 变更日志
```

#### 3.4 质量管控

```
质量检查点：
1. 里程碑评审（每个阶段结束）
2. 功能验收（每个用户故事完成）
3. 回归测试（新功能不影响旧功能）
4. 用户验收（Jackie 最终确认）
```
