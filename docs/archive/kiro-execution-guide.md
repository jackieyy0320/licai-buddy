## 三、API 设计规范（强制）

### 3.1 响应格式

所有 API 必须使用统一响应格式：

```typescript
// 成功响应
{
  "success": true,
  "data": { ... },
  "message": "操作成功"
}

// 错误响应
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "金额必须大于 0",
    "fields": ["amount"]
  }
}

// 分页响应
{
  "success": true,
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 100,
    "pages": 5
  }
}
```

### 3.2 状态码规范

| 状态码 | 含义 | 使用场景 |
|--------|------|----------|
| 200 | 成功 | 正常操作成功 |
| 201 | 创建成功 | POST 创建资源成功 |
| 400 | 请求错误 | 参数校验失败 |
| 401 | 未授权 | 需要登录 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 资源不存在 | 查询的资源不存在 |
| 409 | 冲突 | 资源已存在 |
| 500 | 服务器错误 | 未知错误 |

### 3.3 参数校验规则

**必须使用 Zod Schema 进行参数校验：**

```typescript
import { z } from 'zod';

// 创建交易校验
const createTransactionSchema = z.object({
  type: z.enum(['income', 'expense', 'transfer']),
  amount: z.number().positive('金额必须大于 0'),
  date: z.string().date('日期格式错误'),
  note: z.string().max(200).optional(),
  accountId: z.string().uuid('账户 ID 格式错误'),
  categoryId: z.string().uuid('分类 ID 格式错误'),
});
```

## 五、代码质量检查清单

### 5.1 代码规范检查

| 检查项 | 要求 | 违规处理 |
|--------|------|----------|
| 命名规范 | 文件 kebab-case，组件 PascalCase | 必须修改 |
| 注释规范 | 复杂逻辑必须有注释 | 必须修改 |
| 错误处理 | 必须有 try-catch | 必须修改 |
| 类型定义 | 必须有 TypeScript 类型 | 必须修改 |
| 导入顺序 | 按规范排序 | 建议修改 |

### 5.2 安全检查

| 检查项 | 要求 | 违规处理 |
|--------|------|----------|
| SQL 注入 | 必须使用 Prisma ORM | 必须修改 |
| XSS 攻击 | React 自动转义，不拼接 HTML | 必须修改 |
| 输入验证 | 必须使用 Zod 校验 | 必须修改 |
| 敏感数据 | 不记录密码等敏感信息 | 必须修改 |

### 5.3 性能检查

| 检查项 | 要求 | 违规处理 |
|--------|------|----------|
| 数据库查询 | 避免 N+1 查询 | 必须修改 |
| 列表渲染 | 大数据量使用虚拟滚动 | 建议修改 |
| 图表渲染 | 使用防抖优化 | 建议修改 |

## 七、变更控制

### 7.1 禁止擅自变更

```
以下变更必须经 Hermes 批准：
- 技术栈变更
- API 接口变更
- 数据库 Schema 变更
- 新增依赖包
- 修改核心业务逻辑
```

### 7.2 变更申请流程

```
1. Kiro 提出变更申请（说明原因）
2. Hermes 评估影响
3. Hermes 向 Jackie 汇报风险
4. Jackie 决策是否批准
5. 批准后更新文档，Kiro 执行变更
```

## 八、Review 流程

### 8.1 Review 检查点

```
Hermes Review 检查项：
□ 功能是否完全符合 PRD
□ API 设计是否与文档一致
□ 单元测试是否通过
□ 测试覆盖率是否达标
□ 代码规范是否符合要求
□ 是否有安全问题
□ 是否有性能问题
□ 是否有边界条件遗漏
```

### 8.2 Review 结果处理

| 结果 | 处理方式 |
|------|----------|
| 通过 | 标记完成，进入下一阶段 |
| 小问题 | 指出问题，Kiro 修复后再次 Review |
| 大问题 | 退回重写，重新 Review |
| 多次不通过 | 汇报 Jackie，调整策略 |

## 十、问题处理

### 10.1 遇到问题怎么办

```
1. 首先查看现有文档是否有解决方案
2. 如果没有，向 Hermes 提问（不要自行决定）
3. 等待 Hermes 确认后继续执行
4. 记录问题及解决方案到变更日志
```

### 10.2 问题反馈格式

