## 三、Kiro 管控机制（新增）

### 3.1 文档驱动开发

```
Kiro 必须遵循的文档优先级：
1. docs/prd.md（产品需求）- 最高优先级
2. docs/kiro-dev-brief.md（开发需求）- 开发依据
3. docs/kiro-execution-guide.md（执行规范）- 行为准则
4. docs/figma-design-brief.md（设计规范）- UI 依据
5. docs/system-architecture.md（技术架构）- 技术约束
```

### 3.2 分阶段验收

| 阶段 | 验收内容 | 验收标准 | 负责人 |
|------|----------|----------|--------|
| 项目初始化 | 技术栈、目录结构、基础配置 | 通过构建，无报错 | Hermes |
| 记账模块 | CRUD、筛选、校验 | 10 项验收标准全部通过 | Hermes |
| 账户模块 | 余额计算、转账 | 6 项验收标准全部通过 | Hermes |
| 库存模块 | 商品管理、到期提醒 | 6 项验收标准全部通过 | Hermes |
| 投资模块 | 收益计算、记录 | 6 项验收标准全部通过 | Hermes |
| 报表模块 | 图表、导出 | 5 项验收标准全部通过 | Hermes |
| 数据联动 | 联动逻辑、价格追踪 | 功能验证通过 | Hermes + Jackie |

### 3.3 Review 机制

```
每个功能完成后：
1. Kiro 完成开发 + 测试
2. Kiro 提交 Review 申请（提供链接）
3. Hermes 按检查清单审核
4. 发现问题 → 反馈 Kiro 修复 → 再次 Review
5. 通过 → 标记完成 → 进入下一阶段
```

### 3.4 变更控制

```
Kiro 禁止擅自变更：
- 技术栈（已锁定：Next.js 14 + TypeScript + SQLite）
- API 接口设计
- 数据库 Schema
- 新增依赖包

需要变更时：
1. Kiro 提交变更申请
2. Hermes 评估影响
3. Jackie 决策
4. 批准后更新文档，Kiro 执行
```

## 四、质量管控机制

### 4.1 代码审核清单

```
Hermes Review 时检查：
□ 功能是否完全符合 PRD 描述
□ API 接口是否与文档一致
□ 参数校验是否完整（Zod Schema）
□ 错误处理是否规范
□ 单元测试是否通过且覆盖核心逻辑
□ 集成测试是否覆盖业务流程
□ 代码命名是否符合规范
□ 是否有必要的注释
□ 是否有安全问题（SQL 注入、XSS）
□ 是否有性能问题（N+1 查询）
```

### 4.2 测试审核清单

```
Hermes 审核测试时检查：
□ 正常流程测试是否覆盖
□ 边界条件测试是否覆盖
□ 异常处理测试是否覆盖
□ 空值测试是否覆盖
□ 测试覆盖率是否达标（>80%）
□ 测试用例是否与验收标准对应
```

### 4.3 缺陷等级定义

| 等级 | 定义 | 处理方式 |
|------|------|----------|
| 致命 | 系统崩溃、数据丢失 | 必须立即修复 |
| 严重 | 核心功能失效 | 必须修复才能上线 |
| 一般 | 功能异常但不影响主流程 | 必须修复 |
| 轻微 | UI 问题、提示文案 | 可以延后修复 |
